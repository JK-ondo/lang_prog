# MPPL の仕様

MPPL (Mini Pascal-like Programming Language) は Pascal の部分集合。このコンパイラは MPPL を
読んで CASL II（COMET II 仮想機械のアセンブラ）を出す。

> **出所。** 字句の節は**課題文（マイクロ構文・図1）に基づく確定した仕様**。文法以降は未確定で、
> 課題文を見て埋める。課題文の写しは [../notes/](../notes/) に置き、ここには「この実装が
> 受け付ける言語」を自分の言葉で書く。残る不明点には «要確認» を付けた。

## 字句

ソースは **字句（トークン）と分離子の列**として読む。

```
プログラム ::= { 字句 | 分離子 }
字句       ::= 名前 | キーワード | 符号なし整数 | 文字列 | 記号
```

トークンは全部で **49 種類** — キーワード 28 + 記号 18 + 名前・符号なし整数・文字列の 3。
名前・符号なし整数・文字列は**実体が異なっても同じ 1 種類**として数える。**分離子は字句では
ない。**

### 表示文字

文字列要素と注釈要素の両方がこの定義に乗るので、先に置く。

> **表示文字** = タブ、改行、および ASCII の `0x20`〜`0x7E`

つまり**タブと改行は表示文字に含まれる**。この帰結として、注釈は複数行にまたがれ、文字列の
中にタブを書ける。

表示文字でない文字コード（タブ・改行以外の制御コード）が現れたときは**字句エラーにする**。
課題文は「無視してもよい。もちろんエラーとしてもよい」と両方を許しているが、黙って読み飛ばすと
壊れた入力に気付けないのでエラーを選んだ。

### 分離子

トークンを区切るもので、それ自身はトークンにならない。

| 種類 | 綴り |
| ---- | ---- |
| 空白 | `0x20`（C では `' '`） |
| タブ | `0x09`（C では `'\t'`） |
| 改行 | 下記の 4 通り |
| 注釈 | 下記の 2 形式 |

### 改行 — 4 通りある

```
'\r'   '\n'   '\r' '\n'   '\n' '\r'
```

**この 4 つをそれぞれ「1 つの改行」として扱う。**`\r` は `0x0D`、`\n` は `0x0A`。

実装は「`\r` を読んだら次が `\n` なら一緒に消費」「`\n` を読んだら次が `\r` なら一緒に消費」
になる。これで 4 通りすべてが 1 改行に落ちる。

| 入力 | 行数 | なぜ |
| ---- | ---- | ---- |
| `\r\n` | 1 | 対になる |
| `\n\r` | 1 | 対になる |
| `\r\r` | 2 | `\r` の次が `\n` でない |
| `\n\n` | 2 | `\n` の次が `\r` でない |
| `\r\n\r\n` | 2 | 対が 2 つ |
| `\n\r\n` | 2 | `\n\r` で 1、残った `\n` で 1 |

### 注釈

```
注釈 ::= "{" { 注釈要素 } "}" | "/" "*" { 注釈要素 } "*" "/"
```

入れ子にしない。深さを数えてはいけない。

| 形式 | 注釈要素 |
| ---- | -------- |
| `{ ... }` | `}` 以外の任意の表示文字 |
| `/* ... */` | 連続する `*` `/` が現れないことを除く任意の表示文字 |

表示文字に改行とタブが含まれるので、**注釈は複数行にまたがれる**。

**注釈が開始されたまま EOF を迎えた場合は、EOF までを注釈として処理する。** これは課題文の
明示的な指定であって、**エラーにしない**。閉じ忘れは黙って許される。

### 名前 (識別子)

```
名前 ::= 英字 { 英字 | 数字 }
英字 ::= "a".."z" | "A".."Z"
数字 ::= "0".."9"
```

- 数字から始められない。**`_` は英字に含まれない。**
- **英大文字と小文字は区別する。** `X` と `x` は別の名前。
- **キーワードは予約されている。** キーワードと完全に一致する綴りは名前ではない。キーワードは
  小文字のみなので `Begin` は名前になる。
- 長さの上限はない。「あまりにも長い行はないとしてよいが、あったとしても実行時エラーを起こして
  はいけない」という指定があるので、固定長バッファで受けない。

### 符号なし整数

```
符号なし整数 ::= 数字 { 数字 }
```

- 符号を含まない。`-5` は「`-` と `5`」の 2 トークンで、負数は構文で作る。
- **値の範囲は 0 〜 32768。** 上限は 32767 ではない（`-32768` を書くために 32768 が必要）。
  `32769` 以上は範囲外エラー。
- 桁を足しながら検査する。全部読んでから変換すると `99999999999999` で整数があふれる。
- 先行ゼロ `007` は 7 として許す。マイクロ構文の「数字 { 数字 }」がこれを認めており、値を
  制限する記述もない。MPPL に 8 進数の概念がないので解釈の余地もない。

### 文字列

```
文字列     ::= "'" { 文字列要素 | "'" "'" } "'"
文字列要素 ::= "'" と改行以外の任意の表示文字
```

- `'`（アポストロフィ）で囲む。中に `'` を書きたいときは `''` と 2 つ重ねる（これで 1 文字）。
- **改行は入れられない**（文字列要素でない）。閉じる `'` の前に改行が来たらエラー。
- **タブは入れられる**（表示文字であり、`'` でも改行でもない）。
- EOF に達したらエラー。注釈と違って救済の指定はない。

#### 長さ

**文字列の長さ = マイクロ構文の `{ }` の繰り返し回数。** `''` は 2 文字で 1 と数える。

| 綴り | 長さ | 中身 |
| ---- | ---- | ---- |
| `''` | 0 | （空） |
| `'a'` | 1 | `a` |
| `''''` | 1 | `'` |
| `'don''t'` | 5 | `don't` |
| `''''''` | 2 | `''` |

**この長さは課題3 の制約規則で使う。** 段階1 の時点で正しく持っておく必要がある。

#### `''''` の切り方 — 最長一致の罠

`''''` は **「長さ 1 の文字列」1 個**であって、「長さ 0 の文字列」2 個ではない。最長一致規則が
そう決める。一方 `''` 単独は長さ 0 の文字列 1 個。ここは実装で必ず踏む。

### キーワード (28 種類)

課題文の番号つきで示す。**番号は 1 起点で 49 まで**（記号と `NAME` `NUMBER` `STRING` を含む通し
番号）。この番号は課題文から来る外部の約束なので、実装の enum にも**値を明示して**写す。

| 番号 | 綴り | 番号 | 綴り | 番号 | 綴り | 番号 | 綴り |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 2 | `program` | 9 | `then` | 16 | `not` | 23 | `readln` |
| 3 | `var` | 10 | `else` | 17 | `or` | 24 | `writeln` |
| 4 | `array` | 11 | `procedure` | 18 | `div` | 25 | `true` |
| 5 | `of` | 12 | `return` | 19 | `and` | 26 | `false` |
| 6 | `begin` | 13 | `call` | 20 | `char` | 47 | `read` |
| 7 | `end` | 14 | `while` | 21 | `integer` | 48 | `write` |
| 8 | `if` | 15 | `do` | 22 | `boolean` | 49 | `break` |

キーワードはすべて小文字。`read` `write` `break` だけ番号が離れている（課題文で後から足された
順）。

名前・符号なし整数・文字列は 1 / 27 / 28（`TNAME` / `TNUMBER` / `TSTRING`）。

### 記号 (18 種類)

課題文の識別子名を併記する。**`TLE` は `<`、`TLEEQ` は `<=`** であることに注意 — C の慣習では
`LE` が `<=` を指すので、名前から推測すると逆になる。

| 番号 | 綴り | 識別子 | 番号 | 綴り | 識別子 |
| ---- | ---- | ------ | ---- | ---- | ------ |
| 29 | `+` | `TPLUS` | 38 | `(` | `TLPAREN` |
| 30 | `-` | `TMINUS` | 39 | `)` | `TRPAREN` |
| 31 | `*` | `TSTAR` | 40 | `[` | `TLSQPAREN` |
| 32 | `=` | `TEQUAL` | 41 | `]` | `TRSQPAREN` |
| 33 | `<>` | `TNOTEQ` | 42 | `:=` | `TASSIGN` |
| 34 | `<` | **`TLE`** | 43 | `.` | `TDOT` |
| 35 | `<=` | **`TLEEQ`** | 44 | `,` | `TCOMMA` |
| 36 | `>` | `TGR` | 45 | `:` | `TCOLON` |
| 37 | `>=` | `TGREQ` | 46 | `;` | `TSEMI` |

| 綴り | 用途 | 綴り | 用途 |
| ---- | ---- | ---- | ---- |
| `+` | 加算 / 単項プラス | `(` | 括弧開き |
| `-` | 減算 / 単項マイナス | `)` | 括弧閉じ |
| `*` | 乗算 | `[` | 添字開き |
| `=` | 等しい | `]` | 添字閉じ |
| `<>` | 等しくない | `:=` | 代入 |
| `<` | より小さい | `.` | プログラムの終わり |
| `<=` | 以下 | `,` | 並びの区切り |
| `>` | より大きい | `:` | 型の区切り / 出力の桁数 |
| `>=` | 以上 | `;` | 文・宣言の区切り |

MPPL に無い表示文字: `/`（単独。除算は `div`）、`!` `&` `|` `%` `^` `~` `"` `@` `#` `$` `?`
`\` `_` `{` `}`（`{` `}` は注釈）。これらが出てきたら字句エラー。

### 最長一致規則

> 字句として 2 つ以上の可能性があるときは、最も長い文字の列を字句とする。

これを外すとほぼ全部壊れる。

| 入力 | 正しい切り方 | 間違えると |
| ---- | ------------ | ---------- |
| `<=` | `<=` 1 個 | `<` `=` の 2 個 |
| `<>` | `<>` 1 個 | `<` `>` の 2 個 |
| `>=` | `>=` 1 個 | `>` `=` の 2 個 |
| `:=` | `:=` 1 個 | `:` `=` の 2 個 |
| `readln` | `readln` 1 個 | `read` `ln` の 2 個 |
| `''''` | 長さ 1 の文字列 1 個 | 長さ 0 の文字列 2 個 |

`<` `>` `:` を読んだら**次の 1 文字を覗いてから**決める（先読み 1 文字）。

### 字句エラーの一覧

| 状況 | 例 |
| ---- | -- |
| MPPL に無い表示文字 | `a @ b` |
| 表示文字でない制御コード | `0x01` |
| 閉じていない文字列 | `'abc` |
| 文字列の中に改行 | `'ab` + 改行 |
| 符号なし整数が 32768 を超える | `40000` |
| `/` の次が `*` でない | `a / b` |

**閉じていない注釈はエラーではない**（課題文の指定により EOF までを注釈とする）。

### 段階1 の出力 — 字句とその出現数の表

課題1 の提出物。**標準出力**へ出す。

```
"and " 10
"array " 2
...
"NAME" 38
"NUMBER" 12
"STRING" 2
```

| 規則 | |
| ---- | --- |
| 行頭 | 字句をダブルクォートで囲む |
| 区切り | 1 つ以上の空白文字（空白かタブ） |
| その後 | 出現個数 |
| 1 行 | 1 つの字句のみ |
| 同一視 | 名前は `NAME`、符号なし整数は `NUMBER`、文字列は `STRING` として、実体が違っても同じ字句 |
| 0 個 | **出力しない**（個数 0 の行は存在しない） |
| 分離子 | 字句ではないので出力しない。注釈も出さない |
| 余分な空白 | 字句の中に含まれていてもよい（例の `"and "` は末尾に空白がある） |

**並び順は課題文に指定がない。**種類の定義順（キーワードをアルファベット順に並べ、次に記号、
最後に `NAME` `NUMBER` `STRING`）とする。課題文の例（`and`, `array`, …, `NAME`, `NUMBER`,
`STRING`）と矛盾せず、enum を舐めて 0 でないものを出すだけで済む。

#### 名前の実体ごとの計数（拡張）

課題文の拡張課題。**常に出す**ことにした。基本の表の後に続ける。

```
"NAME" 27
"Identifier" "s" 4
"Identifier" "goukei" 2
"Identifier" "data" 4
```

**1 行は 3 つのフィールドからなる。**

| フィールド | 中身 |
| ---------- | ---- |
| 1 | `"Identifier"`（この語自身も引用符で囲む） |
| 2 | 名前を引用符で囲んだもの |
| 3 | その名前の出現個数 |

区切りは基本の表と同じく 1 つ以上の空白文字。基本の表の `"NAME"` の行は**そのまま残る**
（実体ごとの行はその内訳であって、置き換えではない）。

**並びは出現順**（ソース中で最初に現れた順）。アルファベット順ではない。上の例が
`s` `goukei` `data` の順になっているのがそれで、`data` `goukei` `s` とは並ばない。

この決定は実装の形に効く。**挿入順を保つ入れ物が要る**ので、名前を見た順に末尾へ足していく
線形リストがそのまま使える（名前の種類数は多くないので線形探索で足りる）。ハッシュ表を使う場合は
順序を別に持つことになる。

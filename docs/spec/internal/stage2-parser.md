# 内部仕様 — 段階2（構文解析）

> **未着手。** ここに書いてあるのは「段階1 の設計が段階2 に課している制約」と「段階2 で決める
> ことの一覧」だけ。中身は段階1 が終わり、[../language.md](../language.md) の文法が固まってから
> 書く。先に作り込むと、文法を読んでから変えたくなって無駄になる。

作るモジュール: `ast` `parser`

## 段階1 から受け継ぐもの

| | |
| --- | --- |
| 入力 | `lexer_next` が 1 つずつ返す `token_t` |
| 位置 | すべてのトークンが行・桁を持つ。AST 節点はそれを引き継ぐ |
| 文字列 | `token_t.text` は `source` を指し NUL 終端されていない。AST に持たせるときも同じ規約 |
| 記憶域 | AST はアリーナから取る。解放しない |
| エラー | 記録して続行（[ADR 0003](../../adr/0003-continue-after-errors.md)）。構文エラーからの回復方法は段階2 で決める |

**`lexer` は先読みバッファを持たない。** 再帰下降が要求する「次の 1 トークンを見て決める」は
パーサ側が現在のトークンを 1 つ保持することで実現する。

## 段階2 で決めること

- 解析方式（再帰下降 / 演算子優先順位法）。MPPL の文法は LL(1) に収まるか
- `ast_t` の節点の形。種類ごとに struct を分けるか、タグ付き共用体 1 つにするか
- `--dump-ast` の出力書式
- **構文エラーからの回復**。記録して続行すると決めた以上、どこまで読み飛ばして再開するかを
  決める必要がある。定番は「`;` か `end` まで飛ばす」
- 曖昧さの解消: `if-then-else` の `else` をどの `if` に係らせるか（最も近い `if`）
- 空文（`begin end` や `a:=1;;`）の扱い

## 罠として分かっているもの

段階1 の時点で見えているので、ここに控えておく。

- **空文がある**ため、`begin` の直後に `end` が来ても、`;` が連続しても正当。「文が 1 つ以上ある」
  と仮定した実装は落ちる
- **`else` の係り方**は文法だけでは決まらない。規則として明記する必要がある
- 単項の `+` `-` と二項の `+` `-` が同じトークン。どちらかは文脈で決まる

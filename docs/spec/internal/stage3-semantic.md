# 内部仕様 — 段階3（意味解析）

> **未着手。** 段階2 が終わってから書く。ここにあるのは制約と決めることの一覧だけ。

作るモジュール: `symtab` `semantic`

## 段階2 から受け継ぐもの

| | |
| --- | --- |
| 入力 | 構文的に正しい `ast_t` |
| 位置 | すべての節点が行・桁を持つ。診断はこれを使う |
| 記憶域 | 記号表もアリーナから取る |
| エラー | 記録して続行。ただし未宣言の変数を使った式の型検査は、続けると偽の型エラーを生むので抑制する必要がある |

## 段階3 で決めること

- `symtab_t` の構造。スコープの入れ子をどう表すか（MPPL は手続きの入れ子がないので 2 段で足りる）
- 引ける情報: 名前 → 種別・型・宣言位置・**記憶域の割り当て**
- `--dump-symtab`（クロスリファレンス表）の出力書式 ← 課題の必須出力の可能性が高い
- 型の表現。標準型 3 つと配列型だけなので、小さな struct で足りる
- **記憶域の割り当てを段階3 でするか段階4 でするか** — 段階4 が記号表を探し直さないという約束
  （[architecture.md](architecture.md#段階間の約束) の 2）から、段階3 で決めて記号表に書き込む
  方が筋が通る
- エラー報告の方針: 最初の 1 件で止めるか、複数出すか。複数なら偽陽性の抑制をどうするか

## 段階4 に渡す約束

段階3 を通った時点で次が成り立っていなければ、段階4 が記号表を引き直すことになる。

1. すべての名前の参照先が解決済み
2. すべての式に型が付いている
3. すべての変数に記憶域が割り当てられている
4. エラーが 1 件でもあれば段階4 に進まない

# MPPL → CASL2 コンパイラ 外部仕様書

## 1. 概要

MPPL で書かれたソースファイル 1 つを読み込み、CASL2 のアセンブリプログラムを出力する。
コマンドラインオプションは GCC 13.3.0 の全オプション（約1,740種）から必要なものを選び、名前と意味を GCC に合わせている。

## 2. 起動方法

```
./mpplc foo.mpl
./mpplc [options] foo.mpl
```

| 項目 | 仕様 |
|---|---|
| 入力 | MPPL ソースファイル 1 つ（拡張子 `.mpl`） |
| 出力 | CASL2 ソースファイル。省略時は入力名の拡張子を `.csl` に変えたもの（`foo.mpl` → `foo.csl`） |
| オプションの位置 | ファイル名の前でも後でもよい（`./mpplc foo.mpl -Wall` も可） |

### 実行例

```
./mpplc foo.mpl                  # foo.csl を出力
./mpplc -o out.csl foo.mpl       # out.csl を出力
./mpplc -Wall -Werror foo.mpl    # 警告をすべて有効にし、警告があれば失敗
./mpplc -fsyntax-only foo.mpl    # 解析のみ。何も出力しない
./mpplc --dump-symtab foo.mpl    # 記号表（クロスリファレンス表）を出力
```

## 3. 入力ファイルの制約

### 3.1 入力できるのは 1 ファイルのみ

MPPL は `program 名前 ; ブロック .` の 1 つだけで 1 本のプログラムを構成する言語であり、1 ファイル＝1 プログラムである。
そのため本コンパイラは、ソースファイルを **1 つだけ** 受け付ける。

```
$ ./mpplc foo.mpl bar.mpl
mpplc: error: multiple input files are not supported (foo.mpl, bar.mpl)
```

| 状況 | 動作 |
|---|---|
| 入力ファイルが 1 つ | 通常どおりコンパイルする |
| 入力ファイルが 0 個 | `mpplc: error: no input file` を出力し、終了コード 1 |
| 入力ファイルが 2 つ以上 | 上記のエラーを出力し、何もコンパイルせずに終了コード 1 |
| 拡張子が `.mpl` でない | 警告を出してコンパイルを続ける |

複数のプログラムをコンパイルしたい場合は、コンパイラを 1 ファイルずつ実行する。

```
./mpplc foo.mpl && ./mpplc bar.mpl
```

### 3.2 分割コンパイルは行わない

MPPL には、他のファイルの手続きや変数を参照する構文（`extern`、`import` など）がない。
手続きはすべて同じファイル内で宣言し、`call` で呼び出す。
したがって本コンパイラは **分割コンパイルに対応しない**。

- 1 つのプログラムは 1 つの `.mpl` ファイルにすべて書く。
- 共通の手続きを複数のプログラムで使いたい場合は、それぞれのファイルにその手続きを書く。
- 出力は常に 1 つのプログラム単位（`START` 〜 `END`）となる。入出力用のライブラリルーチンも同じ出力ファイルの中に含める。

#### 将来の拡張（参考・現時点では実装しない）

CASL2 は 1 つのソースに複数のプログラム単位を書くことができ、`START` に付けたラベルは別のプログラム単位から `CALL` で呼び出せる。
そのため、独自拡張として分割コンパイルを入れる余地はある。入れる場合の方針は次のとおり。

- 独自拡張を許す `-std=mppl-ext` を指定したときだけ有効にし、標準の `-std=mppl` ではエラーにする。
- `external procedure p(...)` のような外部手続きの宣言を追加する。
- 外部から参照される手続き名を、CASL2 のラベルの規則（英大文字で始まる 8 文字以内）に合わせて変換する。
- 各ファイルを別々にコンパイルし、出力した `.csl` をつなげてから CASL2 のアセンブラに渡す。

## 4. オプション一覧

「GCC対応」列は、参考にした GCC のオプションを示す。

### 4.1 出力・実行制御（必須）

| オプション | 動作 | GCC対応 |
|---|---|---|
| `-o <file>` | 出力ファイル名を指定する。省略時は `foo.mpl` → `foo.csl` | `-o` |
| `-S` | CASL2 を出力したところで止める（通常の動作と同じ。GCC との互換用） | `-S` |
| `-fsyntax-only` | 字句解析・構文解析・意味解析だけを行い、コードは生成しない | `-fsyntax-only` |
| `-v` | 各フェーズ（字句→構文→意味→生成）の進行状況を表示する | `-v` |
| `--help` | 使い方を表示して終了する | `--help` |
| `--version` | バージョンを表示して終了する | `--version` |

### 4.2 デバッグ・中間表現の出力

| オプション | 動作 | GCC対応 |
|---|---|---|
| `--dump-tokens` | 字句解析の結果（トークン列）を出力する | `-fdump-*` 系 |
| `--dump-ast` | 構文木を出力する | `-fdump-tree-*` |
| `--dump-symtab` | 記号表（クロスリファレンス表）を出力する。課題で `--xref` 相当が必須なら、これを当てる | `-fdump-*` 系 |
| `-save-temps` | 中間ファイル（`foo.tok` / `foo.ast` / `foo.sym`）を削除せずに残す | `-save-temps` |
| `-g` | 生成した CASL2 に、元の MPPL の行番号をコメントとして埋め込む | `-g` |
| `-fverbose-asm` | 生成した CASL2 に、変数名や式などの説明コメントを付ける | `-fverbose-asm` |

### 4.3 警告・エラー制御

#### 全体の制御

| オプション | 動作 | GCC対応 |
|---|---|---|
| `-Wall` | 主要な警告をまとめて有効にする | `-Wall` |
| `-Wextra` | 追加の警告を有効にする | `-Wextra` |
| `-Werror` | 警告をエラーとして扱う | `-Werror` |
| `-w` | 警告をすべて抑止する | `-w` |
| `-fmax-errors=<n>` | エラーを n 個出した時点で打ち切る（0 なら無制限） | `-fmax-errors=` |
| `-pedantic` | MPPL の仕様に厳密に従い、独自の拡張を警告する | `-pedantic` |
| `-std=<std>` | 言語仕様を選ぶ。`mppl`＝標準（デフォルト）、`mppl-ext`＝独自拡張あり | `-std=` |

#### 個別の警告

| オプション | 検出する内容 | 含める先 | GCC対応 |
|---|---|---|---|
| `-Wunused-variable` | 宣言したが使っていない変数 | `-Wall` | 同名 |
| `-Wunused-parameter` | 使っていない仮引数 | `-Wextra` | 同名 |
| `-Wuninitialized` | 代入前に参照している変数 | `-Wall` | 同名 |
| `-Wshadow` | 局所変数・仮引数が大域変数を隠す | `-Wextra` | 同名 |
| `-Wunreachable-code` | 到達しないコード（`return` や `break` の後など） | `-Wextra` | ※ GCC では名前だけ残っていて何もしない。実装は独自 |

### 4.4 最適化（余力があれば）

| オプション | 動作 | GCC対応 |
|---|---|---|
| `-O0` | 最適化なし（デフォルト） | `-O0` |
| `-O1` | 以下の最適化をまとめて有効にする | `-O1` |

`-O1` に含める最適化：

| 個別オプション | 内容 | GCC対応 |
|---|---|---|
| `-fconst-fold` | 定数畳み込み（`2*3` → `6`） | `-ftree-ccp`（GCC に `-fconstant-folding` という名前のオプションはない） |
| `-fdce` | 使われないコードを除去する | `-fdce` |
| `-fpeephole` | CASL2 の命令列の覗き穴最適化（例：`ST GR1,X` の直後の `LD GR1,X` を削除する） | `-fpeephole` |

### 4.5 実行時チェック（CASL2 側にチェックコードを埋め込む）

| オプション | 動作 | 実装のヒント | GCC対応 |
|---|---|---|---|
| `-ftrapv` | 算術演算のオーバーフローを検出する | 演算後に `JOV` でエラールーチンへ分岐させる | `-ftrapv` |
| `-fsanitize=bounds` | 配列の添字範囲をチェックする | MPPL の配列は添字範囲が決まっているので、`CPA` と `JMI`/`JPL` で上下限を比較する | `-fsanitize=bounds` |
| `-fstack-check` | スタックあふれを検出する | 手続きの入口で GR8（SP）とスタック下限を比較する | `-fstack-check` |

## 5. 診断メッセージの形式

GCC と同じ形式で標準エラー出力に出す。

```
foo.mpl:12:9: error: undefined variable 'x'
foo.mpl:20:7: warning: unused variable 'tmp' [-Wunused-variable]
mpplc: error: multiple input files are not supported (foo.mpl, bar.mpl)
```

- ソースに関するもの：`ファイル名:行番号:桁番号: error|warning: メッセージ`
- 行・桁はどちらも **1 起点**。桁は、問題のあるトークンの**先頭**の位置を指す。
- 桁は**バイト単位で数える**（MPPL のソースは ASCII なので、文字数と一致する）。タブは 1 桁と
  数える（タブ幅で展開しない）。
- 警告には、それを有効にしたオプション名を `[...]` で付ける。
- コマンドラインに関するもの：`mpplc: error: メッセージ`（位置を持たないので行・桁は付かない）

## 6. 終了コード

| 値 | 意味 |
|---|---|
| 0 | 成功（警告があっても `-Werror` がなければ 0） |
| 1 | コンパイルエラー、コマンドラインの誤り（入力ファイルが 0 個・2 つ以上、不明なオプションなど）、ファイルを開けない |

エラーで終了した場合は、出力ファイルを作らない（途中まで書いたものは削除する）。

## 7. 対象外（CASL2 には関係しない GCC オプション）

- x86 ターゲット向けの `-m*`（220種）
- `--param`（283種）
- リンカ関連：`-Wl,`、`-l`、`-L`、`-shared`、`-pie`、`-static`（分割コンパイルをしないので不要）
- `-c`（オブジェクトファイルを作る段階がないため不要）
- PIC・PIE 関係：`-fPIC`、`-fpie`
- プリプロセッサ関連：`-E`、`-D`、`-I`（MPPL にプリプロセッサはない）

## 8. 実装の優先順位

1. 起動方法と入力ファイルの制約（1 ファイルのみ）、`-o`、`--help`、`--version`、`-fsyntax-only`
2. `--dump-symtab`（課題で必須なら最優先）、`--dump-tokens`、`--dump-ast`
3. `-Wall`、`-Werror`、`-w`、`-fmax-errors=`、診断メッセージの形式、終了コード
4. `-g`、`-fverbose-asm`、`-v`、`-save-temps`
5. `-fsanitize=bounds`、`-ftrapv`
6. `-O1`（定数畳み込み、DCE、覗き穴最適化）
7. （将来）`-std=mppl-ext` による分割コンパイル

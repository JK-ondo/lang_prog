# 0005. v4 までは MPPL だけを受け付け、Pascal は v5 以降の言語モードとして検討する

- 日付: 2026-10-14
- 状態: Accepted

## 背景

`docs/spec/language.md` は MPPL を「Pascal の部分集合」と書いている。そこから「同じコンパイラで
Pascal も通せるのではないか」という要求が出た。調べた結果、**MPPL は Pascal の真部分集合では
ない**ことが分かった。

### 字句の差分（`language.md` の確定部分に基づく）

| 項目 | MPPL | 標準 Pascal (ISO 7185) |
| ---- | ---- | ---------------------- |
| 大文字小文字 | **区別する**（`Begin` は識別子） | **区別しない**（`BEGIN` = `begin`） |
| 注釈 | `{ ... }` と `/* ... */` | `{ ... }` と `(* ... *)` |
| 整数の範囲 | 0〜32768 のみ。超えたら字句エラー | `maxint` まで |
| 実数リテラル | 無い | `1.5`、`1e10` |
| `/` | 記号として存在しない（除算は `div`） | 実数除算 |
| `..` `^` `@` | 無い | 部分範囲、ポインタ、アドレス |

### MPPL にあって Pascal に無いもの

`call p(x)` という手続き呼び出し、`break`、`return`、`/* */`。この 4 つがあるため、MPPL は
Pascal を含みも含まれもしない。

### 両立しない 3 点

| 衝突 | 例 |
| ---- | -- |
| 大文字小文字 | Pascal の `BEGIN` は予約語、MPPL の `Begin` は識別子 |
| 予約語の差 | Pascal の `var call: integer;` は MPPL では構文エラー |
| 整数の範囲 | Pascal の `100000` は MPPL では字句エラー |

したがって「文法を広げる」ではなく「**言語モードを切り替える**」設計になる。

### 目標機械の制約

CASL II / COMET II は 16 bit 語の整数のみで、浮動小数点演算器を持たない。`real`、ポインタと
`new`、`file` は、それぞれが独立したプロジェクトの規模になる。一方で `for` / `repeat` / `case` /
`function` / `record` / 入れ子手続きは、既存の枠組みの中で実装できる。

## 選択肢

| 案 | 利点 | 欠点 |
| -- | ---- | ---- |
| v4 までは MPPL のみ。Pascal は v5 以降 | 課題の提出物（MPPL → CASL II）を先に確保できる。いま払う代価は「予約語表と大文字小文字の扱いを 1 箇所に閉じる」だけ | Pascal 対応の着手が遅れる |
| いまから 2 モードで設計する | 後の手戻りがない | 段階1 の仕様とテストが倍近くになり、`v1` が遅れる。文法が未確定の段階で 2 言語分の設計をすることになる |
| Pascal 対応をしない | いちばん単純 | 差分を調べた結果が残らず、同じ検討を後でやり直す |

## 決定

**`v1`〜`v4` は MPPL だけを受け付ける。** Pascal は `v5` 以降に `-x mppl` / `-x pascal` のような
言語モードとして検討する。

Pascal 対応に踏み込むとしても、**対象は「COMET II で表現できる範囲の手続き型 Pascal」に限る**。
`real`、ポインタ、`file` は対象外とする。

いま払う代価は 1 つだけ。**予約語の照合と大文字小文字の扱いを `token.c` の表 1 箇所に閉じる**
（`lexer.c` に `strcmp` を直接書かない）。これだけ守れば、後でモードを足すときに `lexer.c` を
触らずに済む。

## 理由

課題の提出物は MPPL → CASL II であり、締切がある。2 言語分の設計を文法未確定の段階で始めると、
`v1` が遅れるうえ、課題文が出た時点で作り直す可能性がある。

一方で「後で足せる形にしておく」代価はほぼゼロで、しかもそれは**モードと無関係に良い設計**
（表駆動、照合箇所の集約）なので、迷う余地がない。

## 結果

- 手順7（`token.c`）で予約語表を作るとき、**照合を関数 1 本に閉じる**。`lexer.c` からは
  「この綴りは予約語か、だとしたらどの種類か」を 1 回問うだけにする。
- `language.md` 冒頭の「Pascal の部分集合」という記述は不正確。`call` / `break` / `return` /
  `/* */` の分だけ Pascal を超えている。この ADR を参照する形で直す。
- `language.md` に 28 個のキーワードの一覧が無い（数だけ）。手順7 までに課題文から写す。
- 覆す引き金: 課題が早く終わって余力が出たとき。その時点で「Rust で作り直す」構想
  （`CLAUDE.md` の「将来」）とどちらを取るかを比べる。

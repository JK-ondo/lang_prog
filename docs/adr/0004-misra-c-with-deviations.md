# 0004. MISRA C を逸脱の記録つきで尊重する

- 日付: 2026-09-27
- 状態: Accepted

## 背景

MISRA C:2012 を尊重する方針とした。しかし MISRA は自動車などの安全critical な組込みソフトウェア
を対象とした規約であり、**コンパイラを書くという用途と正面から衝突する規則がいくつもある**。

MISRA 自身は「文書化された逸脱を伴う適合（compliance with documented deviations）」という形を
認めている。したがって「全部守る」か「参考にするだけ」の二択ではなく、**守る範囲を決めて、
守れないものを理由つきで書き残す**のが規約本来の使い方になる。

> 以下の規則番号と文言は記憶に基づく整理である。課題として形式的な適合を求められる場合は、
> MISRA C:2012 の原文と照合すること。

## 選択肢

| 案 | 利点 | 欠点 |
| -- | ---- | ---- |
| 逸脱を記録して尊重する | 守れる規則の利得を取りながら、破った箇所が全部見える | 逸脱の一覧を維持する手間 |
| 全面的に適合させる | 適合と言い切れる | コンパイラが書けない（後述） |
| 参考程度にする | 手間ゼロ | どこを守っているのか誰にも分からず、規約が飾りになる |

## 決定

守る範囲を決め、守れない規則を下表に逸脱として記録する。新たに逸脱が必要になったら**この
ADR に追記する**（新しい ADR を作らない。逸脱の一覧が 1 箇所にある方が使える）。

## 採用する規則（抜粋）

利得が大きく、このプロジェクトで守れるもの。

| 規則 | 内容 | どう守るか |
| ---- | ---- | ---------- |
| 8.13 | ポインタは可能なかぎり `const` 修飾された型を指すべき | [architecture.md のコーディング規約](../spec/internal/architecture.md#const-は付けられる限り付ける) |
| 8.7 | 単一の翻訳単位からしか参照されない関数・オブジェクトは外部リンケージにしない | モジュール内部の関数は `static` |
| 8.9 | 単一の関数でしか使わないオブジェクトはブロックスコープに置く | ファイル内 static 変数を作らない |
| 15.1 | `goto` を使うべきでない | 使わない |
| 17.7 | 非 void 関数の戻り値は使うこと | 戻り値を捨てない。捨てるなら理由を書く |
| 2.1〜2.7 | 到達しないコード・使われない変数・引数を残さない | `-Wall -Wextra` + `verify:build` の `-Werror` が機械的に検査する |
| 9.1 | 値が不定のオブジェクトを読まない | ASan/UBSan と `clang --analyze` が検査する |

## 逸脱の記録

| 規則 | 内容 | 逸脱の理由 |
| ---- | ---- | ---------- |
| Dir 4.12 / 21.3 | 動的メモリ確保を使わない（`malloc` 等の禁止） | コンパイラは入力の大きさに応じて AST と記号表を作るので、静的確保では書けない。[ADR 0002](0002-arena-allocation.md) でアリーナを選んでおり、**確保点がアリーナの内側 1 箇所に閉じている**ことで、規則の意図（確保の失敗と断片化の制御）は確保方式そのもので担保する |
| 21.6 | 標準ライブラリの入出力関数を使わない | このプログラムの目的が「ファイルを読んでファイルとテキストを出す」ことなので、入出力なしには成立しない。`<stdio.h>` は使う |
| 21.8 | `exit` / `abort` を使わない | アリーナの確保失敗時に終了コード 1 で死ぬと決めている（ADR 0002）。組込みと違い、このプロセスは失敗して終わってよい。ただし**死ぬ箇所はアリーナの確保失敗だけ**に限り、他のどこからも `exit` を呼ばない |
| 19.2 | `union` を使うべきでない | `token_t` が整数値と文字列のどちらか一方を持つ。種類ごとに別の struct を作ると `token_kind_t` との対応を人間が守ることになり、かえって危うい。`kind` が判別子であることを型の不変条件として守る |
| 17.2 | 関数が直接・間接に自分を呼ばない（再帰の禁止） | **段階2 で発生する見込み。** 再帰下降構文解析は文法の再帰をそのまま関数の再帰で表す。表駆動に変えれば規則を守れるが、MPPL の文法に対して読みにくくなる。段階2 に入る時点で方式を決め、再帰を選んだらここに確定として記録する |
| 17.1 | `<stdarg.h>` を使わない | **未決。** 診断メッセージを可変長引数で組むかどうかに依存する。決まったらここに記録する |

## 理由

規則の目的は「危ういことを避ける」であって「規則に従う」ではない。動的確保の禁止は確保失敗と
断片化を避けるための規則であり、アリーナは確保点を 1 箇所に閉じて失敗を 1 箇所で扱うことで同じ
目的を別の手段で満たしている。このように**目的を満たす別の手段があるなら逸脱は正当化できる**。

逆に、目的を満たす手段が無いまま破るのは逸脱ではなく単なる違反なので、この表に書けない。

## 結果

- 逸脱の表がそのまま「この実装が危ういかもしれない箇所の一覧」になる。レビューのときに最初に
  見る場所ができた。
- 段階2 に入るとき、構文解析の方式に「17.2 を守るか逸脱するか」という判断が加わる。方式選択の
  理由が 1 つ増えるので、そこで ADR を書くことになる。
- `-Wconversion` を切っている（`.work` の経過に記録）ことは、MISRA の本質型モデル（10.x）を
  機械的に検査しないという選択でもある。暗黙の型変換は目で見ることになる。

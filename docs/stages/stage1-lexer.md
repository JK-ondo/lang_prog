# 段階1: 字句解析

> **状態: 未着手。仕様は確定済み。** 字句の定義は
> [../spec/language.md](../spec/language.md#字句)、内部設計は
> [../spec/internal/stage1-lexer.md](../spec/internal/stage1-lexer.md)。

## 目的

ソースファイルの文字列を、種類と位置を持つトークンの列に変換し、**字句とその出現数の表**を
標準出力へ出す。文法は一切見ない。

## 対象外

- 括弧の対応、式の形（段階2）
- 名前が宣言されているか、型が合うか（段階3）

## 入力と出力

| | |
| --- | --- |
| 入力 | MPPL ソースファイル 1 本（パスを引数で受ける） |
| 出力（既定） | 字句とその出現数の表を標準出力へ。続けて名前の実体ごとの計数 |
| 出力（`--dump-tokens`） | 位置つきのトークン列。デバッグ用 |
| エラー | 標準エラーへ `file:line:col: error: ...`。終了コードは 1 |

出力の書式は [../spec/language.md](../spec/language.md#段階1-の出力--字句とその出現数の表) が正。

## 不変条件

- トークン列は必ず `TOK_EOF` で終わり、その後も何度読んでも `TOK_EOF`。
- どのトークンも位置（行, 桁）を持つ。位置は 1 起点、トークンの先頭を指す。
- `TOK_EOF` と分離子は字句ではないので、出現数の表に現れない。
- 文字列トークンが持つ長さは、`''` を 1 文字と数えた後の文字数（課題3 で使う）。

## 受入基準

反例を作れる形で書く。「正しく動く」は基準ではない。

### トークンの認識

- [ ] キーワード 28 語すべてを単独で認識する。
- [ ] 記号 18 個すべてを単独で認識する。
- [ ] 名前・符号なし整数・文字列を認識し、実体が違っても同じ種類として数える。
- [ ] キーワードと一致する綴りは名前にならない（`begin` は名前でない）。
- [ ] 英大文字と小文字を区別する（`Begin` は名前）。
- [ ] `_` は名前に使えない。

### 最長一致

- [ ] `<=` `<>` `>=` `:=` をそれぞれ 1 トークンに切る。2 個に割らない。
- [ ] `readln` を `read` + `ln` に割らない。`writeln` も同様。
- [ ] `''''` を「長さ 1 の文字列」1 個に切る。「長さ 0 の文字列」2 個にしない。
- [ ] `''` 単独は長さ 0 の文字列 1 個。

### 分離子

- [ ] 空白・タブ・注釈はトークンを生まず、後続トークンの桁が正しくずれる。
- [ ] 改行 4 通り（`\r` `\n` `\r\n` `\n\r`）をそれぞれ 1 行として数える。
- [ ] `\r\r` と `\n\n` は 2 行、`\n\r\n` は 2 行。
- [ ] 注釈 2 形式（`{}` と `/* */`）を認識し、入れ子として数えない（`{ { }` は最初の `}` で閉じる）。
- [ ] 注釈が複数行にまたがれる（改行は表示文字なので注釈要素になる）。
- [ ] **注釈が閉じないまま EOF に達しても、エラーにせず EOF までを注釈とする。**
- [ ] 分離子が交互に連続しても正しく飛ばす（`{c} /*c*/ x` で `x` を得る）。

### 文字列

- [ ] `''` を 1 文字の `'` として扱い、長さを 1 と数える。
- [ ] タブを含められる。
- [ ] 改行が来たらエラー（開き `'` の位置を指す）。
- [ ] EOF に達したらエラー（注釈と扱いが違う）。

### 符号なし整数

- [ ] `32768` は通る。**`32767` が上限ではない。**
- [ ] `32769` 以上はエラー。
- [ ] `99999999999999` でも整数があふれず、範囲外エラーになる。

### エラーと境界

- [ ] MPPL に無い表示文字（`@` など）は、その位置を指したエラーで拒否する。黙って読み飛ばさない。
- [ ] 表示文字でない制御コードもエラーにする。
- [ ] `/` の次が `*` でなければエラー。
- [ ] 空ファイルは表を 1 行も出さず、終了コード 0。
- [ ] 末尾に改行がないファイルを正しく処理する。
- [ ] 1 行 1000 文字以上の入力でも実行時エラーを起こさない。
- [ ] エラーが 1 件でもあれば終了コード 1。エラーは記録して続行し、複数件報告する。

### 出力

- [ ] 出現数 0 の字句の行を出さない。
- [ ] 並びは種類の定義順（キーワード → 記号 → NAME → NUMBER → STRING）。
- [ ] 名前の実体ごとの計数を続けて出す。

## テストケース一覧

これがこの段階のテスト仕様書。ケースの書式は [../../tests/README.md](../../tests/README.md)、
置き場所は `tests/cases/cli/` と `tests/cases/stage1-lexer/`。

**「根拠」の欄が空のケースは作らない。** 仕様のどの条項から導いたか言えないケースは、実装を
写しただけの可能性が高い。

### 表の読み方

| 列 | 意味 |
| -- | ---- |
| 状態 | ` ` 未着手 / `W` 書いた（落ちる） / `P` 通った |
| 引数 | `.argv` か `.args` に書く引数。「既定」はオプションなし（＝出現数の表が出る） |
| 終 | 期待する終了コード（`.code`） |
| 検査 | 期待値ファイルを置く対象。`out` / `err` / `out(空)` は「空であることを検査する」 |
| 根拠 | 導出元の仕様条項。`§` は [外部仕様](../spec/compiler-spec.md)、それ以外は[字句仕様](../spec/language.md)かこのファイルの受入基準 |

**診断の文言はこの表に書かない。** 文言は外部仕様 §2〜§5 が持っている。ここに写すと 3 つ目の
複製になり、必ず食い違う。「根拠」の列からたどること。

エラーがあるケースの `out` は必ず空になる（§6。エラー時は成果物を出さない）。

### `tests/cases/stage1-lexer/` — 字句解析

既定動作（出現数の表）で確かめるものと、`--dump-tokens` で確かめるものがある。**位置と綴りを
見たいものだけ `--dump-tokens`** を使う。出現数の表では位置が見えないため。

`--dump-tokens` の出力書式は外部仕様 §4.2 が持つ（1 行 1 トークン、区切りはタブ 1 つ）。

#### 各種の認識

| 状態 | ケース | 引数 | 終 | 検査 | 確かめること | 根拠 |
| ---- | ------ | ---- | -- | ---- | ------------ | ---- |
| | `keywords` | 既定 | 0 | out | キーワード 28 語すべてが 1 回ずつ数えられる | 受入基準「トークンの認識」 |
| | `symbols` | 既定 | 0 | out | 記号 18 個すべてが 1 回ずつ数えられる | 同上 |
| | `name-vs-keyword` | 既定 | 0 | out | `begin` はキーワード、`Begin` は名前（大小を区別） | 同上 |
| | `name-forms` | 既定 | 0 | out | 実体が違う名前がすべて `NAME` に集まる | 出力仕様「同一視」 |
| | `name-underscore` | 既定 | 1 | out(空), err | `_` は名前に使えず字句エラーになる | 字句「名前」 |

#### 最長一致

| 状態 | ケース | 引数 | 終 | 検査 | 確かめること | 根拠 |
| ---- | ------ | ---- | -- | ---- | ------------ | ---- |
| | `longest-symbols` | 既定 | 0 | out | `<=` `<>` `>=` `:=` が各 1 トークン。`<` `=` に割れない | 最長一致規則 |
| | `longest-keywords` | 既定 | 0 | out | `readln` `writeln` が `read`+`ln` に割れない | 同上 |
| | `longest-quotes` | 既定 | 0 | out | `''''` が `STRING` **1 個**（2 個ではない）。`''` も 1 個 | 同上 |
| | `string-length` | `--dump-tokens` | 0 | out | `''''` の長さが 1、`'don''t'` が 5 | 不変条件（課題3 で使う） |

`longest-quotes` は個数（1 か 2 か）だけを見る。**長さは出現数の表に現れない**ので、長さの検査は
`string-length` に分けて `--dump-tokens` で行う。

#### 分離子

| 状態 | ケース | 引数 | 終 | 検査 | 確かめること | 根拠 |
| ---- | ------ | ---- | -- | ---- | ------------ | ---- |
| | `separators-mixed` | 既定 | 0 | out | 空白・タブ・注釈が交互に続いても正しく飛ばす | 字句「分離子」 |
| | `newline-four` | `--dump-tokens` | 0 | out | `\r` `\n` `\r\n` `\n\r` が各 1 行 | 字句「改行」 |
| | `newline-pairs` | `--dump-tokens` | 0 | out | `\r\r` `\n\n` が 2 行、`\n\r\n` が 2 行 | 同上 |
| | `comment-brace` | 既定 | 0 | out | `{ }` 形式を飛ばす | 字句「注釈」 |
| | `comment-slash` | 既定 | 0 | out | `/* */` 形式を飛ばす | 同上 |
| | `comment-multiline` | `--dump-tokens` | 0 | out | 注釈が改行をまたげる（改行は表示文字） | 同上 |
| | `comment-pseudo-nest` | 既定 | 0 | out | `{ { }` が最初の `}` で閉じる（入れ子にしない） | 同上 |
| | `comment-unterminated` | 既定 | 0 | out, err(空) | 閉じないまま EOF でも**エラーにならない** | 同上（課題文の明示） |

改行のケースは**行番号を見ないと確かめられない**ので `--dump-tokens` を使う。出現数の表は
分離子を数えないため、改行が 1 行か 2 行かが出力に現れない。

`comment-unterminated` の `err(空)` が肝心。**エラーが出ないこと**がこのケースの主張なので、
標準エラーが空であることを検査する。

| ---- | ------ | ---- | -- | ---- | ------------ | ---- |
